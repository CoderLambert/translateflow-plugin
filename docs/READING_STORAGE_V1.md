# Reading storage V1

Issue #233 implements the protocolVersion 2 repository behind #232 access/service. Persisted domain rows remain schemaVersion 1 and reuse `src/shared/reading` validators; there is no second UI storage model. This delivers a storage layer. Product collection controls, a real learning-center page, downloads and the Release A human flow remain #234–#236.

## Ownership and compatible rollback

Only `src/background/reading-record/idb.js` accesses IndexedDB. It lazily opens `translateflow-reading-records`, version 1. The existing `ai_bilingual_translator` version 2 cache, dictionary OPFS and `chrome.storage` consent are not Reading stores. Reading does not migrate, clear or write those channels. Disable/default-runtime replacement is the rollback path; it detaches invalidation publication and closes owned connections without deleting the database.

`createReadingRepository({ now = Date.now, randomId = () => crypto.randomUUID(), onCommit = null } = {})` is synchronous and pure. It opens no database until a method is invoked. It implements the eleven #232 callbacks: `readPolicy`, `read`, `prepareOperation`, `mutate`, `cancelOperation`, `readInvalidationState`, `openExport`, `checkExport`, `readExportChunk`, `finishExport`, `cancelExport`. `setInvalidationPublisher(null | function)` detaches/replaces publication. `close()` synchronously closes the native connection and clears transient list cursors; native transactions already admitted still finish or abort according to their final guard and native completion. A committed receipt is not retrospectively rolled back. Publisher failure after native completion cannot turn a real commit into a failed save.

The coordinator wires the default factory into the existing service/subscriptions. Fixture injection remains explicit. Only the owner closes the default repository; callers retain ownership of injected repositories. Learning-center availability remains false until its actual artifact exists; `OPEN_LEARNING_CENTER` therefore remains `READING_NOT_READY` in the production package at this stage.

## Native schema and bounded metadata

| Store | Canonical or internal content | Key / indexes |
| --- | --- | --- |
| `records` | Record row, exact application bytes, stable list projection and native-derived site/document relation | `record.recordId`; recent `[-lastLookupAt, recordId]`, page, page/recent |
| `snapshots` | Immutable SourceSnapshot row | `[recordId, sourceSnapshotId]`; record |
| `artifacts` | Immutable ResultArtifact row | `[recordId, artifactId]`; record |
| `pages` | Current aggregate plus bounded empty-page generation tombstone | `pageKey`; recent, expires |
| `meta` | Single consent/exclusions source, capacities and independent revisions | `state` |
| `receipts` | Operation token digest, bounded artifact digest/ack receipts, lookup-count marker and cancellation tombstone | owner/operation; expires |

New databases are created atomically by the native upgrade transaction. Existing store key paths/indexes and metadata are checked before use. Only an absent `meta/state` key initializes the default state: when `get` returns `undefined`, `getKey` checks existence in the same transaction. A persisted `undefined`, `false`, `null`, `0`, empty string/object or any other invalid metadata returns `READING_STORAGE` without resetting canonical rows or generations. A future database version returns `READING_UNSUPPORTED_VERSION`; malformed schema/meta, native open failure and abort return a recoverable storage error. No repair path deletes or resets data. `versionchange` closes the old connection. A blocked request is refused; while its uncancellable native open is still pending, retries do not create more native open requests. Its eventual successful connection is immediately closed after refusal. Retry after failure can reopen a valid database.

Consent generation changes on each accepted global enable/pause patch. The origin's policy revision changes on its accepted patch, so exclude/re-enable cannot revive its old token. Other retained origins keep their own revision. Data generation increments on clear even when empty, with consent/exclusions preserved. Page generation increments on page deletion even when empty. Ordinary append changes record/catalog/export/page revision, not global data generation. Viewing changes the real record/viewed revision, export revision and that record's page revision in the same RW transaction, preserving other pages and the global catalog order/revision. Thus Content sees the summary revision change and its minimal invalidation signal, while a global list cursor remains valid. Cancel receipts change no exported history row.

At most 200 origins are actively excluded. Auxiliary origin rows are bounded by 200 + the existing 128-operation budget; empty page metadata is bounded by 10,000 + 128. Unexcluded origin/empty-page tombstones expire after every token that could reference them has expired. Known live tokens retain their origin/page identity until expiry; defaults do not silently recycle a revoked version. Persisted receipts are bounded at 128 operations, with at most 256 artifact acknowledgements per operation, and prune only after token expiry. There is no event log or durable second pending-operation store. BEGIN stores only authoritative revision/TTL metadata and does not create an empty record or persist selected text.

## Transaction and acknowledgement contract

Hashing and source-digest calculation occur before the transaction. Every transaction is driven by native request success callbacks; no network, browser API, DOM read, timer or arbitrary promise is awaited while it is active. The adapter rechecks the synchronous native-derived access guard before opening the transaction and at the final request callback. A request's `onsuccess` is not an acknowledgement: the repository resolves only on `transaction.oncomplete`; abort rejects and rolls back all rows/indexes/receipt/accounting together. This follows the [IndexedDB transaction lifecycle](https://www.w3.org/TR/IndexedDB-3/#transaction-lifecycle).

Final RW save reads current consent, targeted site policy, data/page generation, record revision and receipt; rechecks registered owner/navigation/source/selection/expiry and immutable identities; checks exact canonical capacity; then atomically appends rows, receipts/count marker, projection/aggregate and billed bytes. The source language is the bounded immutable metadata retained by #232's actual BEGIN registry, not inferred from an answer. The snapshot digest is verified against its saved source strings. An internal `readPolicy` is only the service's preliminary native-authority/origin flag read; it does not treat a not-yet-derived `siteExcluded` field as authorization for BEGIN. Dispatch and final mutation still enforce the complete access/policy contract.

Same operation's basic result and later reliable Rich artifact increment lookup count once. Same artifact ID/digest returns its original acknowledgement with `duplicate:true`; changing its payload is rejected. New artifact IDs append immutable rows. Assistant append leaves an existing record's lookup count unchanged. A first explicit Explain may create its own record with the domain's required initial lookupCount 1; later assistant turns do not create another lookup increment. A new explicit lookup for an existing proven location increments once. New `recordId:null` always creates a new candidate UUID: no word/page auto-merge. Existing reuse requires an explicit record/revision and `sameProvenLocation` evidence including native document generation.

A revision conflict does not overwrite the whole record or repeat a Provider call. The consumer retains the completed result, obtains current detail/source authorization and a fresh explicit BEGIN if necessary, then retries storage. If delete, clear, pause/re-enable, site exclude/re-enable, expiry or cancellation linearizes first, old save is refused. If a save commits first, cancellation returns its actual committed receipt; it does not promise rollback. Lost delivery can retry an unchanged artifact and receive the original receipt. Worker restart loses the #232 transient operation/export capabilities; it does not enable an old client token to bypass registration.

## Reads, pagination and accounting

List views use the stored projection from the same selected snapshot as the selected result preview; they do not issue one get-record per item. Pages are maintained/queried aggregates. Recent records sort `lastLookupAt DESC, recordId ASC`; limits default to 30 and cap at 100, with the actual UTF-8 response budget. Search is bounded literal case-insensitive text over saved previews/metadata, never regex, Provider or dictionary access. Complete detail reads remain available offline and after a dictionary disappears.

List cursors bind native owner/document/navigation/authority, query/filter/limit, consent/data/catalog and Content page revision. One pagination chain occupies one reserved slot, bounded at 128 concurrent pending/active chains. A successful continuation consumes its old cursor and replaces it with a new opaque cursor in the same slot. Concurrent/consumed/expired cursors are stably `READING_STALE_OPERATION`; a failed continuation keeps its unchanged cursor until TTL. Restart a list after a lost response; list delivery is not the export retry protocol. TTL is fixed for the chain and cannot be extended indefinitely by paging. Viewing does not invalidate catalog pagination, while a committed catalog mutation does.

Content page summary returns only record ID/revision/saved anchor/completed-assistant flag plus this page's count/revision; Content recording state has no global counts/URLs/artifacts/context. Explicit Content detail checks the stored native-derived page relation. Private/sensitive/unknown access fails closed through #232, before repository calls.

Application capacity is exactly 10,000 records / 64 MiB canonical UTF-8 JSON rows, 64 KiB per artifact and 256 snapshots/artifacts per record. Canonical rows are counted once; projections/indexes/receipts and native engine overhead are distinct bounded overhead. New record capacity exhaustion does not disable consent. Existing append is permitted if remaining bytes and per-record limits fit. Physical `QuotaExceededError` maps distinctly to `READING_QUOTA`; old readonly list/detail/export and deletion remain separate paths. A viewed metadata update refused by quota/capacity falls back to the actual old readonly detail, without inventing a viewed timestamp. Deletion deducts its actual billed rows and removes all indexed snapshot/artifact rows; clear sets canonical count/bytes to zero while preserving consent/exclusions.

## Consistent bounded export

Export freezes owner/exportRevision/exportedAt. Each chunk and finish opens a new short readonly transaction and checks live revision/policy; no message holds a transaction open. Data/consent/site/viewed/append/delete/clear changes interrupt the next chunk or finish. The reader streams canonical rows in record ID / snapshot ID / artifact ID order, with only row IDs/UTF-16 offset/phase in its cursor. It never calls getAll for the library or stores a whole-library JSON copy. One large record can span many blocks.

Raw chunks are at most 256 KiB, and escaped JSON framing remains within the 1 MiB response budget. Prefix selection never splits a surrogate pair. #232 owns the single current retry chunk and rejects old/unknown/out-of-order cursor capabilities; each buffered retry still checks stored policy/revision. EOF is not a downloaded-file acknowledgement: finish validates the exact owner/current revision/sequence/EOF, after which #235 may create its local Blob. Cancel/worker interruption before finish requires restart. A confirmed finish cannot promise retrieval of a copy already delivered. There are no download permissions, private temporary files or durable export copies.
