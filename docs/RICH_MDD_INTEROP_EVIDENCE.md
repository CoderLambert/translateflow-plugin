# MDD resource interoperability evidence

The checked-in `tests/fixtures/mdd-interop/interop.mdx` and `.mdd` are tiny
synthetic format-interoperability fixtures. `interop.mdx` has one record that
references a local 2×2 PNG, a short PCM WAV, and a reviewed class-only CSS file
inside the sibling MDD. The record also contains one hostile remote image
reference and inert script markup to prove the viewer never follows or runs
record-supplied active content. They contain no dictionary corpus, remote
asset, or runtime vocabulary.

Both files were generated by the independent MIT-licensed
[zhansliu/writemdict](https://github.com/zhansliu/writemdict) writer at commit
`f0240b30cabd2f0470d3ee1a0641fc7f8c38dcf5`. The checked-in
[`corpus-lock.json`](../tests/fixtures/mdd-interop/corpus-lock.json) pins the
writer commit, writer source and license checksums, artifact hashes, and the
payload checksums. The generator imports that checkout from outside this
repository; it does not vendor the writer source. Its Python 3.13+
compatibility shim maps the writer's removed `cgi.escape` reference to the
stdlib `html.escape` function. It also pins the writer's date input to
2026-09-30 so the binary headers and fixture hashes are repeatable.

To regenerate the small checked-in pair, use an unmodified checkout of the
pinned commit outside the repository:

```sh
git clone https://github.com/zhansliu/writemdict.git /tmp/writemdict
git -C /tmp/writemdict checkout f0240b30cabd2f0470d3ee1a0641fc7f8c38dcf5
python3 scripts/generate-mdd-interop-fixture.py \
  --writer-checkout /tmp/writemdict \
  --out-dir tests/fixtures/mdd-interop
```

Run `node scripts/certify-mdd-interop.mjs --writer-checkout /tmp/writemdict --regenerate`
to verify source and artifact checksums and produce a bounded JSON evidence
report under `/tmp/translateflow-mdd-184/evidence` (or set
`MDD_INTEROP_EVIDENCE_DIR`). Add `--large-range-evidence --bulk-bytes 104857600`
to run the synthetic range-I/O check. The report stores metadata and hashes,
not payload bytes.

The range-I/O evidence uses a separate 100 MiB-class corpus generated by the
same pinned writer with deterministic SHAKE-256 incompressible filler and one supported
PNG probe after the filler records. It is explicitly synthetic and is written
only under `/tmp/translateflow-mdd-184/evidence`;
the extension reads the fixture through the indexed source interface and does
not load all resource record objects or unpack the MDD. The Python writer must
hold its generated input and output while creating this performance corpus;
that generator-side memory is separate from measured extension import and
lookup memory. The application performance evidence records source byte ranges
and resource response sizes so index reads and a small asset lookup can be
compared with the full physical MDD size.
