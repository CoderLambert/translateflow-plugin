# 开发流程效率约定

本约定落实开发复盘中的改进，配合 [CONTRIBUTING.md](../CONTRIBUTING.md) 使用，不增加任务状态机，不解除 Issue 的依赖、验收、独立审核或仓库保护要求。目的是减少丢失源码、迟发现影响面、重复验证和重复上下文带来的返工。没有可信 token/费用统计时，不估算节省比例。

## 开工：一次闭合影响面

主 Agent 刷新当前 main、任务决策、执行者与相关 PR 后，记录简短任务卡：目标与非目标、基线、依赖、文件所有权、验证入口、停止条件。只读受影响的合同与调用链，不扫描全部历史 Issue。

构建或迁移任务先核对「入口 → 构建输入 → 实际产物 → 消费者 → CI paths/env」。检查消费者是否仍读旧包、工作流路径过滤是否覆盖改动、测试是否自行造包，以及生产资源是否进入精确映射。只整理本任务受影响的链，不重新选择整个技术方向。

UI 与后台并行前，先对齐 DTO、用户事件、ACK/错误状态、授权时机、取消和迟到结果归属。未经确认的合同差异交回协调者，不在组件内复制业务规则。实际用户闭环决定验收，组件准备或构建成功不等于功能交付。

## 实现：少委派，集中反馈

小任务主 Agent 直接完成。确需具名角色时，给最小任务卡、合同链接、明确工作目录和文件范围；不用完整会话代替输入。遵守现有并发上限和独立工作区要求，共享文件只有一个写入者。

角色配置和实际运行信息首次使用时核对；会话重载、角色配置、启动权限或环境发生变化时复查相关项，不为每个任务重复空测试。不可观察的模型或权限字段标记未知，不靠模型自报身份证明。

开发中先运行受影响的定向检查；集中处理当前有效反馈后再形成可审核提交并推送。不按每个文件或普通小修复触发一轮 CI/全量审核。确有失败、依赖冲突或需远端环境才能验证时可提前推送，并说明原因；不等积累成难以审查的大批改动。

## 验证与审核：复用证据，保留门禁

提交前仍运行 CONTRIBUTING 要求的 `npm run validate`，浏览器、迁移或发行变化仍运行适用的实际产物测试。新断言应覆盖用户结果或风险，避免只镜像实现。失败不能通过降低断言、扩大权限或清空数据解决。

已有证据应标明提交、命令、结果、产物来源，以及相关环境/依赖/fixture。只有这些输入可确认相同，才引用既有本地证据；脏工作区、生成资源、环境或参数不同不能仅凭相同 SHA 判定重复。变更后重查受影响部分，无法确认影响范围时执行完整相关检查。

验收者复现最终用户闭环；独立 reviewer 亲读准确 head 的 diff、调用链和必要反例，不仅复述作者总结，也不要求无理由重复作者全部测试。证据复用不替代当前 head 必需 CI、GitHub 必需审查、独立审核、人工验收或 expected-head 合并保护。

等待 CI 使用工具支持的 watch/等待能力，避免频繁查询同一状态。完成后一次核对最新 head、checks、正式 reviews、自动审核摘要与 inline 评论；检查成功、审核执行失败、审核发现问题是不同事实。不把绿色 CI 当作全部审核通过。

## 暂停与交接：先保全源码

实现源码使用持久隔离工作区；临时目录只用于可再生产物和测试 profile。暂停、结束或移除工作区前，协调者逐项核对：

- branch/head 与远端 ref 是否实际一致；不以本地 commit 或聊天中的 SHA 代替远端保全。
- 本任务未提交 diff、所属未跟踪源码是否已在持久路径保全；明确记录未同步项。
- 若当前授权允许推送，推送聚焦任务分支；若不可推送，保存精确 patch 与所属源码快照，并记录恢复方法。不得包含认证、用户数据、私有词典或无关个人文件。
- 检查备份实际包含需要恢复的源码，并验证可恢复性；测试日志、截图、产物和总结不能代替源码。
- 将 branch/head、完成内容、实际测试、待审 PR、未提交修改、阻塞与下一条动作写入当前 Issue；同步失败时提供持久本地交接并明确未同步。

发现旧源码已丢失时，先确认远端或备份的可恢复性，不能以旧摘要或 PASS 宣称实现仍存在；恢复或重做须说明实际来源和验证状态。用户暂停后不继续产品开发，不声称会话结束后仍会自行运行。

## 信息与计量：按需汇总

稳定合同保留在规范文档，易变进度集中在当前 Issue checkpoint；PR 描述面向最终 diff，父 Issue 仅给状态索引与链接。不要在聊天、PR、多个规范中复制整套进度。

完整验证日志留本地证据；聊天与审核输入只提供结论、必要失败片段、变化及证据位置。先用确定性脚本检索/汇总，避免让模型重新阅读完整日志、会话或未变化的文档。只在需要判断异常、风险或取舍时调用模型，不为展示协作额外启动 Agent。

任务计量工具见 [PR #276](https://github.com/CoderLambert/translateflow-plugin/pull/276)；该工具独立交付，本约定不以其合并或原生事件全覆盖为前提。工具可用后，将 start/stage/finish 附加到已有执行命令，按任务结束、暂停或用户要求生成报告，不逐事件调用模型或提交日志。计时包含等待，重叠跨度不累加作工作时间；未知调用量、token、未匹配事件保持 UNKNOWN，不回填历史猜测值。
