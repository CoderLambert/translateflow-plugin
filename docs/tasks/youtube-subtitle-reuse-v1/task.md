1. 对原 source/pipeline/controller 增加实际模块组合的失败回归；传输、任务端口和展示用边界 double。
2. 在原 pipeline 内把完成 Set 改为有界结果 Map；补在途去重、可保留成功结果的 cancelPending，旧任务清理只作用于自身。
3. Controller 保存当前快照并按视频/来源/轨道/cue时段/文本校验结果；换句清旧译文、重叠按原序显示；原文/off同步停队列，保存设置不阻塞停止；启动/停止以生命周期防止晚到回调重新挂载。
4. 固定上游 scheduler 原文件及 Git blob，独立运行提取验证。不把这项验证标成已生产接入；不擅自修改整个项目许可证。

## 2026-10-21 短字幕译文迟到修复

用户真实页面反馈 AI 译文间歇空白、出现后瞬间消失，并明确要求修复。目标是在短 cue 开始前备好已有字幕的译文，同时继续禁止过期结果串句。前述“不启用预取”是早前切片边界；本次授权仅增加完成本缺陷所需的有界窗口，不接入完整上游 scheduler。

- 在现有 snapshot 增加 `upcomingCues`（未来 12 秒最多 5 条已知定时 cue）和 `seeking`；MAIN 完整轨道、已启用 TextTrack 的完整 cues 提供窗口，DOM 不预测未来。
- 沿用现有 pipeline 的单个 processQueue、requestId、取消、成功结果表、Provider 和缓存；定时 cue 不等待 DOM 稳定延迟，当前 cue 优先，未启动的过期窗口淘汰。seek 撤销后仍等原 transport 结束才启动下一执行，不把消费者取消当实际资源释放。
- 保留严格的当前句/时钟显示检查、重叠顺序、原文/off 零新调用、配置和缓存撤销。不复制 GPL 代码、不变更权限、持久化 schema 或凭据配置。
- 主 Agent 串行修改 `src/content/subtitles/{source,pipeline,controller,renderer}.js`、两个 source adapter、定向测试/E2E及本任务证据。先补失败回归，再实现、检查、重建 `dist/extension/`，执行相关 Chromium/MV3 流程。真实页面与 mock 浏览器证据分别记录。无提交、推送、合并授权。

可读性补充：浏览器截图实证原有底部控件会遮挡译文。控件移至播放器上沿；E2E 断言控件与字幕区域交叠面积为 0，不改变原生控制栏或增加功能。

真实 Chrome 补充：首轮预取修复的 mock 验收通过，但用户视频 11.78–21.51 秒采样仍无译文，不能标为已修复。实际页面没有 TextTrack，DOM 同时匹配 segment 与父 visual-line 导致原文重复；滚动文字持续变化也会延后请求并拒绝仍然可见的旧短语结果。本轮补充选择器互斥读取、连续追加最多等待 800ms、仅在完整原文短语仍可见时保留译文，配套慢 Provider 的生产包 DOM 集成回归。必须重建并重新加载后在同一已登录 Chrome 页面复验；无完整轨道的 DOM 回退仍受真实 Provider 延迟限制。

用户反馈看不到字幕 UI 后，实测设置条顶部为 -276px，透明度 0.42。顶部设置条方案已由用户否决，CSS sticky 在真实播放器的 overflow:hidden 下也有失败回归；不作为交付。按用户明确要求改为底部原生操作栏一个“译”入口，点击后在上方展开当前三个控件，支持 Escape/外点关闭与焦点恢复；renderer 仅为控制栏重建维护自身按钮绑定，生命周期完整清理。播放器重建时 preset 选项显示原始 inherit 的问题有生产包失败回归，挂载时复用现有 rebuildPresetSelect 修复。真实页面重新加载、截图与效果判断另记到 late-subtitle-fix-report。
