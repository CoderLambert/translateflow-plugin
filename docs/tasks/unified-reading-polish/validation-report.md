## 失败、修正与限制

- 新协议残片/旧缓存测试先在旧版失败，修复后通过；初次正则漏转义导致加载失败，已修正，原日志保留。
- 旧Popup在三种终态后被晚到进度覆盖，3项回归先失败后通过；部分完成没有错误样式也先失败后修复。
- 页面重绘旧版出现2项失败，取消用例原本通过。新增缓存场景一度把期望数量写成19，实际18缓存+2新译应为20；纠正后专项通过，未削弱原文变化/取消断言。
- 真实页面首轮曾报告18段完成但没有可见译文；当时没有足够DOM时序证据，不能宣称已经确认该次事件的唯一根因。随后以合成重绘复现了同类丢失并修复。
- 0.8.52真实页即便完成35段且机械校验通过，截图仍有截断编号残片，已否决为最终交付证据；最终校验补齐单项、双引号开头与缺失闭引号。真实模型也出现格式尝试耗尽后的 MALFORMED_RESPONSE，失败日志原样保留。单靠加强校验时，真实页重试仍失败；随后修改既有单段降级的传输方式，最后的真实复验才通过，不能将前面的失败算作成功。
- 对公开合成输入比较JSON约束开/关：开启3/3符合合同，关闭2/3；没有证据支持关闭正常批次的约束，因此普通请求保留原方式；仅在既有的单段降级处用无响应ID的纯文本传输。该小样本不代表模型总体成功率。
- 真实YouTube播放仍受既有登录/机器人验证阻塞；本轮字幕验收来自合成播放器与此前本地模型对照，不冒充真实公开视频长期播放。
- 最后真实测试依然触发格式恢复，22次请求、36.5秒反映额外调用开销；不宣称普遍加速，最终截图的片段重组在语义流畅度上仍受本地模型能力限制。
- 内容规则只识别明确协议特征，不证明所有译文的语义质量。网页完成后再次重绘、改变原文或模型持续返回坏结果时，仍可能需要用户重试。
