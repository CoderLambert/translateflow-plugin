# 产品完整度审核与优先补齐清单

审核日期：2026-10-20。对象为已合入 main 的 **TranslateFlow 0.8.42**，合入 SHA `8c2b8ec0f65b7afc30be5065c49619b16b2872ea`；对应归档 SHA `ced284d8d59e1abfbedcf9b46b33c1a71623c995` 的 tree 相同。

本次为主 Agent 的产品路径／代码审核及定向 Chromium 观察，不是独立人工审计，也没有修改产品源码、提交或推送。既有本地文档和完成记录保留。本报告仅在本地新增。

## 1. 总体判断

核心能力已经具备：网页翻译、划选查词、本地词典、AI 解释、缓存、YouTube 字幕、Reading 历史和最小生词复习都有实现。当前适合继续个人使用与定向试用；面向新用户的首次使用、联网授权管理、收藏数据正确性和长期数据保留还没有完整收尾。

建议下一轮优先完成 **授权与恢复 → 收藏数据正确性 → 首次使用说明 → 真实环境验收**，并把基本备份恢复纳入长期使用的补齐范围。进阶复习算法、云同步、其他浏览器等属于后续产品扩展，不能与当前正确性缺陷混为一类。

本次不以测试数量、历史任务状态或主观百分比替代完成度判断。任务卡仍为 working／reviewing 的部分功能已经存在；只有沿当前调用链和用户结果核对后，才能认定缺口。

## 3. 已确认的问题

P1 表示建议下一轮先处理，影响用户控制、持久数据正确性或首次使用；P2 表示恢复体验、信息表达或长期使用能力需要补齐。以下没有把未复现的猜测列为确定缺陷。

### 3.1 P1：联网同意无法通过当前界面撤回保存

**触发：** 当前单词或文字方式是免费在线，已有有效联网同意。在设置中取消「允许将待翻译文本发送给免费翻译服务」。

**观察：** 保存按钮立即禁用；原同意记录仍存在；刷新设置后复选框重新选中。用户没有通过该控件完成撤回的路径。这不是“拒绝首次授权仍联网”的证据，问题是撤回操作无法完成。

**根因：** [MachineTranslationSection.tsx](../../../src/options/MachineTranslationSection.tsx) L68–L72 在 `online && !consent` 时禁用保存；[machine-translation-client.ts](../../../src/options/machine-translation-client.ts) L36–L42 也在发送前拒绝 `consent=false`。后台 [translation-preferences.js](../../../src/background/translation-preferences.js) 本身可以存储空同意记录，但正常界面走不到该保存。

**补齐建议：** 提供明确的撤回动作或允许保存未授权状态；保留方法选择，不自动换方法。说明全局／本站授权的作用范围，禁止撤回后的新上传，保留历史数据。撤回不应依赖其他 AI／模型资源恰好可用。

**验收：** 同意 → 撤回 → 重开设置仍为未同意；划词、页面主按钮、自动任务均受执行保护；重新同意必须明确点击。分别覆盖全局授权和网站覆盖。

**证据：** `consent-withdrawal.json`：保存禁用、原授权保留、刷新后重新选中；无 AI 请求。

### 3.2 P1：在线／AI 译文收藏丢失真实语种和来源

**触发：** 单词方式免费在线，目标语言设置为 Japanese，用微软线路翻译单词并收藏到生词本。

**观察：** 实际请求目标为 `ja`，卡片正确显示「在线译文 · 微软翻译」；生词本却保存为：

```json
{
  "sourceLanguage": "auto",
  "targetLanguage": "zh",
  "sources": [{ "sourceId": "ai-translation", "packId": "translation-v1" }]
}
```

此次 AI 请求数为 0，外部响应为合成 fixture。上例仅摘录字段，不包含用户私人数据。

**根因：** [result-model.js](../../../src/content/selection/result-model.js) L74–L78 仅为 Chrome 本地保留 `browserPair`；[translation-actions.js](../../../src/content/selection/translation-actions.js) L6–L10 以该字段决定语种与来源，其他翻译结果统一回退到 `auto`／`zh` 和 `ai-translation`。AI 的非中文目标收藏也会走同一回退分支；本次浏览器复现的是免费在线日语场景。

**影响：** 生词本无法保留真正的服务来源，语种和后续按语种去重存在错误风险。[VocabularyBook.tsx](../../../src/learning-center/views/VocabularyBook.tsx) L154 当前还直接展示技术性的 packId，用户看到的来源不够直观。

**补齐建议：** 由结果 DTO 传递真实引擎、实际 Provider 和有效语言对，收藏直接消费该结构；查询卡片、Reading 与生词本的来源语义保持一致。旧条目没有充分数据时不要猜测恢复真实来源或语种。

**验收：** 免费在线、Chrome 本地、AI、词典 × 至少两种目标语种；查询、缓存命中、收藏、重启后保持同一来源和语种。跨语种不能错误合并为一条。

**证据：** `vocabulary-provenance.json`：请求 `ja`、收藏 `zh`／`ai-translation`、AI 请求数 0。

### 3.3 P1：首次使用的授权恢复不够直接，说明仍有旧规则

**触发：** 默认免费在线、没有有效联网同意，用户直接划词。

**观察：** 当前面板提示「请先确认允许向所选翻译服务发送文本」，可见按钮只有关闭和重试；授权设置入口位于展开「切换方式」后的「修改默认方式」。直接重试不能解决缺少同意的问题。阻止隐式上传的保护有效，恢复步骤没有在错误位置直达。

**代码：** [controller.js](../../../src/content/selection/controller.js) L222–L226 将该错误交给通用失败状态；[popover.js](../../../src/content/selection/popover.js) L205–L225 主要提供重试；设置链接位于 [method-controls.js](../../../src/content/selection/method-controls.js) L67。

**说明冲突：** [README.md](../../../README.md) L228–L235 仍称默认开启浏览器释义、首次查词准备本地模型，并要求开启「翻译前优先查询已安装词典」。这些与现有两类单选和已移除的独立路由开关冲突。L233 还保留旧「保存全局设置」说明，与当前不同区域独立保存关系不够清晰。

**补齐建议：** 首次错误状态提供明确的确认／设置恢复入口，保持拒绝后零联网；通过内联引导或简短首次配置流程交代单词方式、文字方式、联网范围和可选资源。统一 README 与界面实际操作。

**验收：** 全新临时 profile、不配置 AI／词典／模型，能按可见提示完成第一次在线查词；拒绝后清楚知道当前状态；旧开关名称不再出现在当前使用步骤中。

**证据：** `consent-recovery.json` 与 `first-use-consent.png`；无 AI 请求。

### 3.4 P2：服务已进入冷却，但设置页的冷却详情未接通

**触发：** 固定微软线路的连接检查返回合成 429，Retry-After 为 120 秒。

**观察：** 后台已记录约 120 秒冷却，界面仅显示「服务已限流，正在冷却」；可展开的服务恢复诊断区没有出现。

**根因：** [MachineTranslationSection.tsx](../../../src/options/MachineTranslationSection.tsx) L22 和 L64–L67 依赖 `state.health`；新的 [readTranslationPreferences()](../../../src/background/translation-preferences.js) L88–L100 没有返回该字段，前端持续使用空数组。

**补齐建议：** 将所选线路健康状态纳入一致的公开偏好 DTO，提供可理解的剩余时间、重试与手动改线入口；保持固定模式失败不自动跨线路／跨方法切换。

**验收：** 429／403／网络冷却能显示相应服务和实际剩余时间，刷新设置后状态一致，恢复检查不在后台定时偷偷联网。

**证据：** `cooldown-diagnostics.json`：约 120 秒冷却、返回值无 health、诊断节点数量 0。

### 3.5 P2：AI 功能触发前的可见标识不充分

在线查词结果的可见标签通常为「理解／分析／用法」。其 ARIA 已写明 AI，打开后也有 AI 标题；普通视觉用户在触发前不容易知道它会使用已配置 AI 服务，可能发送文本和产生服务费用。

依据：[ai-detail.js](../../../src/content/selection/ai-detail.js) L237–L250 与 [catalog-content.js](../../../src/i18n/catalog-content.js) 的 `content.ai.*` 文案。当前“必须明确点击”的机制已具备，本项只要求把动作性质在点击前表达清楚。

建议用统一 AI 分组、小标或明确标签，在触发前交代使用的服务；不必给每个动作增加确认弹窗。验收时同时检查可见文本、屏幕阅读器和零自动 AI 请求。

### 3.6 P2：长期学习数据的备份恢复不完整

Reading 已有分块 JSON 导出，不能说产品完全没有导出。现有导出入口位于 Reading 分支，调用 Reading export 协议；生词本的数据独立存储，没有相应导出入口，当前读取／复习／删除客户端也没有恢复 API。未发现用户可用的 Reading JSON 导入恢复入口。

依据：[App.tsx](../../../src/learning-center/App.tsx) L120–L129、L142 和 L186–L190，[client/export.ts](../../../src/learning-center/client/export.ts)，[生词本客户端](../../../src/learning-center/client/vocabulary.ts)，[Reading 消息合同](../../../src/shared/reading/constants.js)。生词本目前上限为 200 条／4 MiB，见 [vocabulary-book.js](../../../src/shared/vocabulary-book.js) L2–L4；这使数据带走和继续积累更值得优先考虑。

建议补齐用户显式的本地导出／导入恢复，明确是否包含 Reading、生词、AI 笔记和复习状态。版本、容量、冲突、损坏文件和敏感内容都应有清晰处理；凭据默认不随学习数据导出。不要仅提高容量上限掩盖长期保留问题。

验收应在一次性临时 profile 中完成导出 → 导入 → 重启，核对语种、来源、条数和学习状态；不能只断言文件下载成功。

## 5. 建议的补齐顺序与结束标准

### 第一轮：用户控制和持久数据正确性

处理 3.1、3.2、3.3；分别补授权同意／撤回、方法 × 语种 × 收藏、全新用户第一次查词的流程覆盖。

结束标准：用户能清楚控制联网；非中文学习数据正确；新用户按当前文案可完成第一次使用。旧数据恢复采取保守策略，禁止无依据改写来源。

### 第二轮：服务恢复与长期使用

处理 3.4、3.5、3.6；接通健康状态、统一 AI 可见标识，确定并实现最小本地数据备份恢复范围。

结束标准：用户知道失败原因和下一步；知道何时使用 AI；已积累的学习数据可以带走并恢复。

### 第三轮：真实场景收口与支持范围

固定包指纹，完成真实本地模型、目标词典和 YouTube smoke，明确支持的浏览器及安装升级方式。不可用环境保留 NOT VERIFIED，不以 mock 或增加测试数量代替。

SRS／FSRS、Anki、云同步、多浏览器、移动端等可根据产品定位另排；目前不把它们列为本轮必须修复的缺陷。
